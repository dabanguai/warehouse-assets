# 映场设备仓管 · 开发版 0.1.0

## 当前能力

uni-app + Vue 3 + TypeScript前端，共用Java 17 + Spring Boot 3.5.7后端；MySQL保存业务数据，文件保存在服务端本地目录。支持微信小程序编译和H5运行，接口地址和请求、响应字段沿用现有约定。

| 模块 | 代码能力 |
| --- | --- |
| 登录与人员 | 密码哈希、7天会话、管理员/仓管/查询角色，服务端权限；管理员新增账号 |
| 基础资料 | 设备大类、具体类别、设备、别名、剧组组别、外借公司新增编辑，两级分类和设备启停 |
| 库存 | 资产归属与仓库分离，有编号逐台、无编号按数量；当前在库、可供、在外及分仓来源 |
| Excel | 真正读取xls/xlsx、选择工作表、调整列映射、保存模板、名称候选、编号及货号拆分 |
| 期初 | 识别标蓝归属、横向剧组去向、差异和空白；确认后事务建立在库及期初在外 |
| 日常单据 | 新购、出库/增补、预留、分批/异地归还、延期、调拨、出售/报废、盘点 |
| 一致性 | 草稿与确认分离、整单事务、版本检查、确认幂等、同内容文件重复入账保护 |
| 排期 | 完整日期区间、同类多行共同核算、编号连续可用、预计归还条件、逾期不释放、延期冲突 |
| 更正 | 编号及资产归属更正，未归还单据来源分配更正，前后记录保留 |
| 照片与导出 | 单据照片上传和鉴权读取；真实xlsx供货反馈及剧组来源导出 |

正式数据默认从空库开始，只有两方资产库和两地仓库预置。期初在外的原发货仓无法从总库确定时记录为“来源仓待核实”，不归入北京或横店可供库存；归还时进入实际接收仓。

## 本机启动

环境：Java 17、Maven 3.6.3或更高、MySQL 8.4、Node.js 24、Python 3.10或更高。Python负责xls/xlsx单元格、颜色及导出处理；业务接口、权限、库存和事务由Java负责。MySQL需要在启动前创建数据库及应用账号。

数据库管理员执行以下SQL，密码替换为实际值：

```sql
CREATE DATABASE warehouse CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
CREATE USER 'warehouse'@'localhost' IDENTIFIED BY '替换为实际数据库密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES ON warehouse.* TO 'warehouse'@'localhost';
```

远程部署时按实际来源主机配置账号。Flyway在启动时执行版本化建表脚本，业务数据默认从空库开始。

在项目根目录执行：

```powershell
npm install
python -m venv .venv-excel
.\.venv-excel\Scripts\python.exe -m pip install -r apps/api/python/requirements.txt
npm run setup
# 在.env填写MYSQL_URL、MYSQL_USER、MYSQL_PASSWORD
npm run dev
```

本地开发界面：[打开H5](http://127.0.0.1:5173)。API默认端口3100。若分别启动，使用`npm run dev:api`和`npm run dev:h5`。

本次工作区已安装依赖，已生成`.env`。首次管理员账号为`.env`中的`ADMIN_USERNAME`，随机密码为`ADMIN_PASSWORD`；密码不打印到启动日志，不包含在源码交付包中。`npm run setup`不会覆盖已有配置，修改初始化密码也不会重置已创建账号。

`DATA_DIR`相对后端工作目录解析，默认`../../data`即项目根目录data，原始Excel和照片保存在其中的files目录。业务数据保存在`MYSQL_URL`指定的MySQL库。不要将真实data、`.env`、`.cache`、迁移导出文件或虚拟环境提交到代码仓库。后端启动入口统一加载根目录的`.env`；IDE直接运行时，将工作目录设为后端模块并配置同样的环境变量。

后端单独构建及启动：

```powershell
npm run build:api
npm run start:api
```

构建产物为`warehouse-api-0.1.0.jar`。生产环境运行Java包不需要Node.js；配置环境变量，并保持Python解析器、文件目录及H5产物可访问。Maven使用本机settings.xml，镜像地址无法连接时需要先修正该配置。

## 构建与检查

```powershell
npm run check
npm test
npm run build:h5
npm run build:weixin
```

H5产物为`apps/miniapp/dist/build/h5`。构建后重新启动API服务即可在3100端口访问H5，无需开发服务器。打包部署时通过`H5_DIR`指定该目录；`WORKBOOK_SCRIPT`指定workbook.py，`PYTHON`指定Python解释器。

默认测试执行Java单元测试和前端交互测试。MySQL集成测试需要显式指定独立测试库，缺少配置时会标记跳过；测试会清空该库业务表，只接受`warehouse_test`或`warehouse_test_`开头的数据库名。

```powershell
$env:WAREHOUSE_TEST_MYSQL_URL='jdbc:mysql://127.0.0.1:3306/warehouse_test?serverTimezone=Asia/Shanghai'
$env:WAREHOUSE_TEST_MYSQL_USER='测试数据库账号'
$env:WAREHOUSE_TEST_MYSQL_PASSWORD='测试数据库密码'
$env:PYTHON=(Resolve-Path '.venv-excel/Scripts/python.exe').Path
# 可选：指定真实总库，缺少此项时只跳过真实总库测试
$env:WAREHOUSE_TEST_WORKBOOK='总库.xls的绝对路径'
npm test
```

微信产物为`apps/miniapp/dist/build/mp-weixin`，由微信开发者工具导入。正式联调前填写`apps/miniapp/src/manifest.json`中的微信AppID，并在小程序环境变量中设置`VITE_API_BASE=https://实际服务域名/api`，配置微信合法请求和上传域名。当前未进行微信真机、发布审核或公网部署。

微信本机开发时分别打开两个PowerShell窗口，在项目根目录执行：

```powershell
# 窗口一：后端
npm run dev:api
```

```powershell
# 窗口二：小程序编译，保持运行
npm run dev:weixin -w @yingchang/miniapp
```

微信开发者工具导入`apps/miniapp/dist/dev/mp-weixin`，使用普通编译。仅本机模拟器联调HTTP服务时，在开发者工具本地设置中开启“不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书”。真机需要配置可访问的服务地址，不能使用电脑的`127.0.0.1`。

启动入口为登录页，页面就绪后才进入库存；已有会话失效时统一返回登录页。遇到旧版本的`reLaunch:fail timeout`，停止原小程序编译进程，重新执行窗口二的命令，待编译完成后点击微信开发者工具“编译”。

## 使用顺序

管理员在“管理”页依次维护：**设备大类 → 具体类别 → 设备**。例如：机械器材 → 伸缩摇臂 → 天蝎45呎。大类和具体类别均支持新增、改名、停用；编辑具体类别可调整其所属大类。设备建档时先选择大类，再选择该大类下的具体类别。

期初可从总库建立分类：选择“期初建账”上传总库，解析后查看“总库分类”。机械总库按表内标题识别“机械器材”大类，具体类别沿用类型列及合并单元格下的分类。大类未识别时可填写。

“导入类别”只建立分类资料，不要求先补齐库存数量，也不创建设备、资产或出入库记录。现有同名类别会复用，未归入大类的类别会补上关联。已有类别属于其他大类时提示核对，不直接覆盖。随后可继续核对数量；若不单独导入类别，确认期初入账时会一并建立分类、设备和库存，失败则整单回滚。

旧版本类别及Excel中未明确大类的类别显示为“待归类”。管理员为其设置大类后，已有设备自动显示完整分类，原设备ID、编号、归属和库存数量保持不变。入库中确认新增设备时可选择两级分类；未选择时保留原表类别，未归入大类的类别列入待归类。

库存页支持按大类及具体类别筛选，切换大类会清除上一次的具体类别条件。设备、剧组、归还明细或具体类别列表为空时，选择框禁用并显示下一步提示，不打开空白选择列表。

旧SQLite结构版本1和2均可通过迁移工具转入MySQL。版本1未归类类别的group_id保持为空，类别、设备、资产和单据ID沿用原值。

1. 管理员登录，维护两级分类及设备，或直接上传总库建立品种后归类。
2. 期初上传总库，选择工作表；标蓝为2号库，未标蓝为1号库。
3. 核对资产总量、两仓、在外去向、单位、同名行及出售维修备注。空白不是零，不能仅为了入账而清除真实差异。
4. 选择实际基准日并确认。已包含在期初中的历史出库单不能再次扣减。
5. 日常入库区分新购和归还；出库可手工或Excel，确认来源及编号后入账。
6. 剧组详情查询计划与实际来源；提前归还、增补和延期通过关联单据操作。

Excel入账规则：货号空白全1号库；`2`全2号库；`2*N`表示2号库提供N，其余归1号库。备注配件不拆库存；独立小件可显式标记“不计库存”。无编号设备不会强制生成虚假的实物编号。

## 数据及安全边界

| 项目 | 说明 |
| --- | --- |
| 正式数据 | `data/`不放联调样例，本轮未确认原始总库为正式库存 |
| 联调数据 | 使用`.cache/ui-verification`与自动测试独立目录，不随源码包交付 |
| 文件访问 | 上传文件名不参与服务器路径拼接，照片通过鉴权接口访问 |
| Excel处理 | Python只读单元格及样式，不执行宏或公式；导出字符串按文本写入 |
| 身份 | 客户端只保存会话令牌，角色由服务端实时查询，不信任客户端角色字段 |
| 事务 | MySQL InnoDB整单事务及数据库写锁覆盖库存计算到提交，失败回滚；同确认键返回原结果；库存快照在同一读事务中加载 |

## SQLite历史数据迁移

迁移前停止原后端写入，备份SQLite及整个data目录。创建空MySQL数据库，在`.env`配置目标连接，先构建Java包，随后导出并导入：

```powershell
npm run build:api
npm run db:export -- data/warehouse.sqlite .cache/warehouse-migration.json
npm run db:import -- .cache/warehouse-migration.json
npm run start:api
```

导出只读原SQLite，输出文件已存在时拒绝覆盖。导入仅接受空业务库，替换两方归属和仓库种子数据，在同一事务内导入并核对各表数量，任意记录失败整批回滚。已创建管理员的目标库也会拒绝导入，应使用新的空库，不通过清空现有库解决。

账号密码哈希、类别、设备、单据、库存、占用、照片元数据、审计及确认幂等记录保留。旧登录会话不迁移，人员需要重新登录。原始Excel和照片仍使用原data/files目录，迁移文件不包含文件内容；更换服务器时同时复制该目录。完成后核对账号登录、设备及编号、两仓数量、期初在外、单据和照片，妥善保管原库备份及迁移文件。

## 尚未完成的正式能力

- 语义AI服务未接入，当前采用规范名称、别名、数字规格候选与人工确认。
- 历史出库补录及历史余额重算未开放；使用期初和当日日常业务，避免重复扣减。
- 部分归还后的原单来源重分配暂拒绝覆盖，需要分笔核对；已完成业务不能直接删除。
- 自动跨仓运输排期未实现；当前分仓查询、手工调拨和在途接收。
- 排期当前为设备占用列表，尚无月历；照片当前关联整单，尚无行级照片编辑界面。
- 人员目前支持新增及角色设置，尚无密码找回、微信身份绑定和停用账号界面。
- 期初按同设备同归属已有资产阻止重复建立；新增资产使用新购入库。
- uni-app工具链历史依赖审计结果保留在开发验证记录中，发布时需结合官方兼容版本重新核对。
